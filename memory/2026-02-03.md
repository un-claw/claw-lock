## Memory Search Debugging (post-restart)

### Issue
Memory search index builds successfully but `memory_search` tool returns empty results while CLI `openclaw memory search` works fine.

### What We Found
- **Indexing works**: 6/6 files, 361 chunks (11 memory, 350 sessions)
- **CLI works**: `openclaw memory search "taiji"` → 0.769 score MEMORY.md hit
- **Tool broken**: `memory_search(query="taiji")` → empty results, even with minScore=0

### Root Cause: Gemini Batch API
Initial indexing failed because Gemini free tier doesn't support batch embeddings API:
- Batches stuck in "UNKNOWN" state indefinitely
- **Fix**: Disabled batch mode (`remote.batch.enabled: false`)
- After fix, indexing completed in seconds

### Resolution
After a clean gateway restart, `memory_search` tool works perfectly:
- 6 results returned for "taiji principles" query
- 0.78 score on MEMORY.md hit (matches CLI)
- Session transcripts also searchable

The issue was **sync timing** - the gateway needed a fresh restart after indexing to pick up the new embeddings. Not a bug, just operational knowledge.
